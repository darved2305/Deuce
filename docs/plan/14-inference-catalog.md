# 14 · Inference catalog for Person 2's presentation

> **Status: proposed reference (D-261011-HW9), not yet adversarially reviewed.** Tonight's priority is the live demo path; use this after the demo is safe.

This is the runtime catalog for choosing which views the app can show. Person 1 emits measured
time, geometry, confidence, and evidence primitives. Person 3 persists them and computes
aggregates, patterns, and simulations. Person 2 chooses a presentation from fields that are
actually available for that match. A catalog row is not evidence that a result exists.

## 1. Rules for every card, overlay, and number

- Read `match.v1` from `GET /v1/matches/{id}`, windows/events from the analysis artifacts and
  cursor, and sidecars through `GET /v1/artifacts/{id}`. The app must use the same IDs and values
  as the REST API, TypeScript SDK, MCP server, and embed.
- Intersect this catalog with the runtime `timeline.v1` availability entries. Show only
  `available` data or clearly labelled `candidate` data. For `withheld`, `unavailable`, or
  `unknown`, use the returned reason or omit the view. Do not infer availability from the clip
  type or a previous match.
- Every displayed number includes its denominator or confidence and opens its exact evidence
  frames or real clip. For derived rates, show `numerator/denominator`, unit, tier, and source IDs.
  If the schema lacks a denominator or source IDs, do not show the number until the separate
  contract amendment lands.
- Detector scores and geometric residuals are not probabilities. Label them by their actual
  meaning. Never display a percentage as confidence until calibrated against real labels.
- Observed geometry is solid. A single interpolated slot is dashed and excluded from counts,
  events, and referee calls. Longer gaps remain gaps. Predicted trajectories are dashed and
  labelled `PREDICTED` with their prediction horizon and observed evidence range.
- Court animation for a what-if scenario is labelled `SIMULATED`. It starts from a real source
  frame and real measured inputs. A simulated continuation never looks like an observed clip.
- Referee output is labelled `MODEL ESTIMATE`, supports `IN`, `OUT`, `TOO_CLOSE`, and
  `UNOBSERVED`, opens evidence frames, and never changes score without a player confirmation.
- Do not display speed in km/h. Flight time is the supported comparison. Show image-space speed
  only in free play and only with the explicit `px/s` unit.
- All example payload values below say `shape only` unless explicitly attributed to a real result.
  No invented match, clip, detection, or score is used as an example.

## 2. Runtime catalog record

Person 4 must add `timeline.v1` in a separate contract PR before the Android reader consumes it.
The proposed artifact key is
`analysis/{analysis_id}/{engine_version}/tracks/timeline.json`; the optional match reference is
`match.v1.analysis.artifacts.timeline`. Each `data[]` entry identifies an inference and the
actual source fields that are available. Proposed entry fields are:

```text
inference_key: string
availability: "available" | "candidate" | "withheld" | "unavailable" | "unknown"
reason: string | null
source_artifact_ids: string[]
source_event_ids: string[]
time_field: string | null
geometry_fields: string[]
unit: string | null
coordinate_frame: string | null
confidence_field: string | null
state_field: string | null
confidence_meaning: string | null
numerator_field: string | null
denominator_field: string | null
numerator: number | null
denominator: number | null
evidence_frames_ms: number[]
time_range_ms: [number, number] | null
```

`availability` describes the current analysis only. It is not a capability-matrix status. The
catalog may point at `window_result.v1`, `match.v1`, and `camera_path.v1` fields; it cannot add
measurements or repair absent values. `source_event_ids` and explicit numerator/denominator are
additions proposed here because the current `metricSchema` only provides event IDs and integer
counts. Contract changes are listed in §7.
