## Verdict

Keep the native Android, Supabase, R2 and Modal architecture. It fits the phone-first product and keeps video bytes out of the API. **The current walkthrough is not ready to build as written:** the deployed API paths, auth and access policies, multipart signing, event subscription, comparison lookup and deep link still have gaps. The local probes also do not support promising an automatic badminton line call from a handheld phone clip.

This is a read-only review. No files were changed. I reviewed the requested build pack and the relevant research and probe evidence. The final decisions in [11-debates.md](/Users/Hetansh/Github/elevate1.0/docs/11-debates.md) supersede the earlier plans.

## Issues and exact fixes

1. **Resolve the public API route and auth contract.** Choose the Supabase function slug, Hono route prefix and OpenAPI `servers.url` together. Put the observed deployed base URL in the spec and smoke-call `POST /v1/sessions`. Use user JWT auth for app calls and RLS scoped to `auth.uid()` across `matches → sessions/uploads/analyses → artifacts/clips`. Keep server keys out of the phone. Add a scoped, hashed key table and issue/revoke flow before claiming developer API keys; for the demo, use the same owner JWT in the SDK and local MCP. The final endpoint list is in [08-developer-platform.md](/Users/Hetansh/Github/elevate1.0/docs/08-developer-platform.md:22).

2. **Fix badminton calibration and referee semantics.** Use `badminton_singles` when the format is singles. Transform taps from Compose view space to rotated source-image coordinates, store the selected frame PTS and derive the correct singles sidelines. Keep the line result `candidate` or `experimental`; show the evidence and allow confirm/correct. Only the user-confirmed point updates score. Badminton UI should say “landing,” not “bounce.” The calibration mismatch is in [contracts.md](/Users/Hetansh/Github/elevate1.0/docs/contracts.md:21).

3. **Make retries safe and artifact paths deterministic.** Persist multipart `uploadId`, part numbers and ETags; make repeated completion return the same completed state. Give analysis idempotency a unique database constraint and an outbox/dispatch state so a retry cannot create another `analyze.spawn()`. Use stable object keys, for example `analysis/{analysis_id}/{engine_version}/windows/{window_seq}.json` and `clips/{match_id}/{clip_id}.mp4`, and store them with artifact rows. Run one real Deno-to-R2 multipart smoke upload before building the full client.

4. **Finish event and review contracts.** Add a named private Broadcast event, such as `analysis_seq`, and RLS policies that let only the analysis owner receive that topic. The durable `analysis_events` cursor remains authoritative. Add an append-only `point.confirmed` domain event, derive `confirmed_by` from auth and require an idempotency key on confirmation.

5. **Finish comparison, clip rights and offline behavior.** Add a comparison route, such as `GET /v1/matches/{mid}/shots/{shot_id}/comparisons?scope=own&limit=3`, returning clip IDs and rights provenance. Require a real earlier match before presenting this flow. Store canonical artifact IDs, fetch fresh signed URLs after ownership/rights checks, and cache the chosen clip plus overlays for offline replay. Add the Android intent filter and choose how a local MCP link reaches the phone. The clip rights rules are in [12-real-clips.md](/Users/Hetansh/Github/elevate1.0/docs/12-real-clips.md:18).

6. **Narrow the 24-hour deliverable.** Ship one polished badminton post-game flow with the real video, confidence-aware overlays, review and confirmed score. Keep SDK and local MCP read-only over that same `match.v1`. Defer match simulation, opponent predictions, general multi-sport scoring, social features, remote MCP/OAuth, embedded player and widgets until that vertical slice works. The current API should remain the control plane; Edge Functions have a 2-second CPU limit on free, so they are not a video-processing host.

## Recommendation

Keep Kotlin + Compose + Media3, Supabase Auth/Postgres/Edge Functions, private R2 uploads and a Modal vision worker. Build and test one real upload through review before adding platform extras. Treat the app’s moat as evidence-linked history, clear confidence and honest abstention across sessions, not as an unvalidated automatic referee.

For the venue demo, use a rights-cleared real badminton clip for court analysis and the college informal clip as a separately labeled assisted free-play/generalization attempt. TAPIR’s performance on that exact catch clip is **UNVERIFIED**, so preflight it on the target phone and have a video/fixture fallback. The college catch footage cannot prove a badminton line call without a court.

## Three biggest risks

1. The Deno R2 multipart signer and Modal dispatch have no verified end-to-end run; either can block the main upload demo.
2. Current phone-footage probes do not support reliable badminton landing calls, and TAPIR on the proposed venue clip is unverified.
3. Auth/RLS, Realtime policy, developer credentials, prior-match comparison and offline cache are incomplete enough to break the history-and-sharing story.
